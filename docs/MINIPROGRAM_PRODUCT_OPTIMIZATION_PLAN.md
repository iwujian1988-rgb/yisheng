# 小程序产品体验一次性优化计划

> 角色视角：资深产品负责人
> 目标：一次性解决当前“小程序像 demo、OCR/ASR 不可用、AI 未形成商品化能力、模板权重不足、蓝牙发送链路不完整、用户体验稀烂”的核心问题。
> 状态：优化计划稿。确认后可拆成 PRD、开发任务和验收清单。

## 1. 一句话结论

当前小程序的问题不是某一个页面坏了，而是产品主线没有成立。

它现在是：

```text
一堆功能页 + 若干后端接口 + 若干测试页
```

它应该变成：

```text
用户选择内容来源 -> 得到可用文本 -> 审核编辑 -> 发送到电脑 -> 记录结果
```

所有优化都围绕这条主线展开。

## 2. 当前核心问题

### 2.1 前台信息架构混乱

问题：

- 首页没有清晰告诉用户“我能干什么”。
- 模板、AI、OCR、ASR、手动输入、蓝牙发送之间没有形成自然流程。
- 大量内部页面、QA 页面、后台页面混在同一个路由池里，导致产品像 demo。
- 用户无法分辨哪些是正式功能，哪些是开发/测试功能。

影响：

- 用户打开后不知道从哪里开始。
- 模板这种高价值入口被弱化。
- OCR/ASR/AI 虽然有页面，但像隐藏功能。

### 2.2 OCR/ASR 当前不可用

问题：

- 前端有 OCR/ASR 页面。
- 后端有 OCR/ASR gateway。
- 但当前健康检查显示：

```text
ocrConfigured = false
asrConfigured = false
```

说明：

- OCR worker 未配置。
- ASR worker 未配置。
- 用户看到的是“功能不可用”，不是完整体验。

影响：

- 用户点击功能后失败。
- 产品承诺和实际能力不一致。
- 体验非常差。

### 2.3 AI 商品化逻辑不清

问题：

- AI 不应该让用户配置。
- AI 是平台侧配置、后台售卖、用户按套餐使用。
- 当前前端和后端有 AI 调用链，但本地服务显示：

```text
aiConfigured = false
```

说明：

- 当前不是完整真实 AI 创作能力。
- 没有清晰区分“硬件传输版”和“AI 套装版”。
- 未开通用户点击 AI 时没有成熟的转化提示。

影响：

- 用户以为 AI 功能坏了。
- 付费能力无法商品化。
- 后台也缺套餐管理。

### 2.4 模板权重不足

问题：

- 模板应该是最高频、最高确定性的主入口。
- 当前模板入口不够突出。
- 模板没有形成“选择场景 -> 填字段 -> 生成 -> 审核 -> 发送”的强流程。
- 模板与 AI 套餐关系不清：哪些是基础模板，哪些是 AI 增强模板，没有产品定义。

影响：

- 用户不会优先使用模板。
- AI 未配置时，产品缺少可用的核心替代能力。

### 2.5 蓝牙发送和调试能力断裂

问题：

- 首页直接承担蓝牙连接、文本输入、发送、调试日志，职责过重。
- 传输速度设置、系统模式、电脑环境设置存在，但没有完整闭环。
- 没有设备调试中心。
- 没有明确的用户准备流程：插硬件、开蓝牙、电脑输入框聚焦、选择系统、测试发送。
- 编码模式、速度策略、系统模式没有被产品化。

影响：

- 普通用户不知道怎么准备电脑环境。
- 内测/售后也缺少排查工具。
- 硬件不可用时无法快速定位问题。

### 2.6 用户体验文案混入开发语言

问题：

- 页面里出现过类似“主流程”“provider”“mock”“网关”等内部词。
- 用户页面不应出现开发/产品讨论语言。

影响：

- 用户不理解。
- 产品显得粗糙。
- 降低信任感。

## 3. 优化目标

### 3.1 用户目标

让用户打开小程序后，能够在 10 秒内理解：

- 我可以用模板生成文本。
- 我可以用 AI 写一段。
- 我可以拍照识别文字。
- 我可以录音转文字。
- 我可以手动输入。
- 最后都能发送到电脑。

### 3.2 产品目标

建立清晰的商业分层：

```text
硬件传输版：手动输入 + 基础模板 + 发送到电脑
AI 套装版：AI 创作 + AI 增强模板 + AI 整理 OCR/ASR/手动文本
```

### 3.3 技术目标

让每个入口都有明确状态：

- 可用。
- 未开通。
- 服务暂不可用。
- 开发测试模式。

不要让用户看到无意义错误。

## 4. 新产品结构

### 4.1 前台主导航建议

前台普通用户只保留 4 个核心区域：

```text
首页
模板
历史
我的
```

首页承载高频动作。

模板承载场景化生成。

历史承载发送记录和复用。

我的承载账号、套餐、设备、设置、帮助。

### 4.2 首页结构

首页必须从“设备控制台”变成“内容工作台”。

推荐结构：

```text
顶部状态
- 服务状态
- AI 套餐状态
- 设备连接状态

主入口：常用模板
- 工作汇报
- 通知公告
- 邮件润色
- 会议纪要

内容来源
- AI 写一段
- 拍照识别
- 录音转文字
- 手动输入

待发送文本
- 当前文本
- 字数
- 编辑
- 清空

发送到电脑
- 连接设备
- 发送
- 模拟发送，仅开发态

最近发送
- 最近 3 条
- 一键复用
```

### 4.3 模板结构

模板是最高权重模块。

结构：

```text
模板首页
- 搜索
- 常用
- 工作汇报
- 通知
- 邮件
- 会议
- 医疗/护理/专业场景，视业务决定

模板详情
- 场景说明
- 字段填写
- 语气选择
- 是否 AI 增强

模板结果
- 可编辑正文
- 待确认事项
- 继续编辑
- 发送到电脑
```

模板能力分层：

```text
基础模板：硬件传输版可用
AI 增强模板：AI 套装版可用
```

未开通 AI 的用户点击 AI 增强模板：

```text
该模板需要开通 AI 套餐
开通后可自动润色、补全结构并生成更自然的文本。
[联系客服开通] [使用基础模板]
```

### 4.4 AI 创作结构

AI 不做“聊天 demo”优先。

先做任务型创作。

入口：

```text
AI 写一段
```

任务：

- 润色文本。
- 总结要点。
- 写通知。
- 写邮件。
- 写汇报。
- 自定义要求。

流程：

```text
选择任务 -> 输入素材/要求 -> 生成 -> 审核编辑 -> 发送到电脑
```

未开通 AI：

```text
AI 写作需要开通 AI 套餐
请联系客服开通后使用。
[联系客服开通] [返回]
```

AI 服务异常：

```text
AI 服务暂时不可用
请稍后重试，或先使用模板生成/手动输入。
```

注意：

- 用户不配置 AI。
- 用户不看模型。
- 用户不看 provider。
- 用户只看“是否开通 AI 套餐”。

### 4.5 OCR 结构

OCR 必须成为首页一级内容来源。

流程：

```text
拍照/选图 -> 识别 -> 编辑识别结果 -> 下一步
```

结果页操作：

- 发送到电脑。
- 用 AI 整理，AI 套装用户可用。
- 套用模板。
- 保存草稿。

OCR 服务不可用：

```text
图片识别暂时不可用
你可以先手动输入，或稍后重试。
```

如果 OCR 是 AI 套餐权益：

```text
图片识别需要开通 AI 套餐
[联系客服开通]
```

### 4.6 ASR 结构

ASR 必须成为首页一级内容来源。

流程：

```text
录音 -> 转文字 -> 编辑文字 -> 下一步
```

结果页操作：

- 发送到电脑。
- 用 AI 整理，AI 套装用户可用。
- 套用模板。
- 保存草稿。

ASR 服务不可用：

```text
录音转文字暂时不可用
你可以先手动输入，或稍后重试。
```

如果 ASR 是 AI 套餐权益：

```text
录音转文字需要开通 AI 套餐
[联系客服开通]
```

## 5. 套餐与权限设计

### 5.1 用户模式

两种模式：

```text
硬件传输版
AI 套装版
```

### 5.2 硬件传输版

可用能力：

- 连接硬件。
- 手动输入。
- 基础模板。
- 发送到电脑。
- 历史记录。

可见但不可用：

- AI 写作。
- AI 增强模板。
- AI 整理 OCR/ASR/手动文本。

点击不可用 AI 能力：

```text
该功能需要开通 AI 套餐
请联系客服开通。
```

### 5.3 AI 套装版

可用能力：

- 硬件传输版全部能力。
- AI 写作。
- AI 润色。
- AI 总结。
- AI 增强模板。
- AI 整理 OCR/ASR/手动文本。

OCR/ASR 是否纳入 AI 套餐，需要最终确认。

### 5.4 AI 套餐档位

档位：

```text
1 个月
1 年
永久
```

前台展示：

- 当前套餐。
- 到期时间。
- 永久有效标识。
- 联系客服续费。

不展示：

- API key。
- 模型。
- provider。
- AI base URL。

### 5.5 权限字段建议

后端返回建议：

```json
{
  "hardwareEntitlement": "active",
  "aiEntitlement": "active",
  "aiPlanType": "yearly",
  "aiExpireAt": "2027-06-08",
  "features": {
    "basicTemplates": true,
    "aiWriting": true,
    "aiTemplateEnhance": true,
    "ocr": true,
    "asr": true
  }
}
```

前端不自己判断套餐规则，只读后端授权。

## 6. 管理后台优化

后台必须从“设备/用户管理”扩展到“套餐与能力管理”。

### 6.1 新增套餐管理

字段：

```text
套餐名称
套餐类型：1个月 / 1年 / 永久
有效期
包含能力：AI 写作、AI 模板增强、OCR、ASR
状态：启用 / 停用
备注
创建时间
更新时间
```

操作：

- 新建套餐。
- 编辑套餐。
- 上架/下架套餐。
- 查看套餐用户。

### 6.2 新增用户套餐

字段：

```text
用户
手机号/openid
当前套餐
开始时间
到期时间
状态：有效 / 已过期 / 已取消
是否永久
开通来源：后台 / 激活码 / 订单
操作人
备注
```

操作：

- 给用户开通套餐。
- 延期。
- 续费。
- 取消。
- 改套餐。
- 查看开通记录。

### 6.3 激活码体系升级

当前激活码只表达服务开通不够。

建议激活码增加类型：

```text
硬件传输版激活码
AI 1个月套餐激活码
AI 1年套餐激活码
AI 永久套餐激活码
```

激活码字段：

```text
code
planType
duration
features
status
usedBy
usedAt
createdBy
```

## 7. 蓝牙与发送优化

### 7.1 普通用户流程

普通用户不应该先看到编码和技术细节。

流程：

```text
准备电脑 -> 连接设备 -> 发送文本
```

准备电脑：

- 插入硬件。
- 打开手机蓝牙。
- 电脑输入框放置光标。
- 选择电脑系统。

发送页：

- 文本预览。
- 电脑系统。
- 发送速度。
- 发送按钮。

### 7.2 设备调试中心

给开发、售后、内测使用。

入口：

```text
我的 -> 设置 -> 设备调试
```

能力：

- 蓝牙扫描列表。
- RSSI。
- deviceId。
- service UUID。
- write characteristic。
- notify characteristic。
- MTU。
- 编码模式。
- 发送速度。
- 单字符测试。
- 长文本测试。
- 日志导出。

### 7.3 编码模式

普通用户不选择编码。

普通用户只看到：

```text
电脑系统
发送速度
```

调试中心才显示：

```text
编码模式：自动 / VUC / RAW / ASCII
```

默认：

```text
自动
```

## 8. OCR/ASR/AI 可用性修复

### 8.1 状态治理

每个能力都要有 4 种状态：

```text
可用
未开通
服务暂不可用
开发测试模式
```

用户看到：

- 可用：直接进入。
- 未开通：联系客服开通。
- 服务暂不可用：稍后重试或使用替代方式。
- 开发测试模式：只在开发态展示。

开发/后台看到：

- provider 是否配置。
- worker 是否配置。
- 请求是否失败。
- 错误日志。

### 8.2 替代路径

OCR 不可用时：

```text
去手动输入
联系客服
```

ASR 不可用时：

```text
去手动输入
联系客服
```

AI 不可用时：

```text
使用基础模板
手动输入
联系客服
```

## 9. 文案原则

用户页面禁止出现：

- 主流程。
- provider。
- gateway。
- mock。
- API。
- worker。
- 未配置。
- baseUrl。
- token。

用户页面使用：

- 写一段。
- 生成文本。
- 拍照识别。
- 录音转文字。
- 发送到电脑。
- 连接设备。
- 联系客服开通。
- 服务暂时不可用。

## 10. 开发实施顺序

### P0：止血，修复前台主体验

目标：让用户打开首页就知道怎么用。

任务：

- 重做首页信息结构。
- 模板入口最高权重。
- OCR/ASR/AI/手动输入一级露出。
- 删除用户侧开发文案。
- AI 未开通状态统一提示联系客服。
- OCR/ASR 不可用状态给替代路径。
- 首页设备状态降权。

验收：

- 用户第一屏能看到模板、AI、OCR、ASR、手动输入。
- 未开通 AI 点击后不会报错。
- OCR/ASR 不可用时不会进入死路。

### P1：打通内容生成闭环

目标：所有内容来源都能变成待发送文本。

任务：

- 模板结果进入待发送文本。
- AI 结果进入待发送文本。
- OCR 结果进入待发送文本。
- ASR 结果进入待发送文本。
- 所有结果页支持编辑。
- 所有结果页支持发送到电脑。
- 历史记录区分来源。

验收：

- 模板 -> 生成 -> 编辑 -> 发送成功。
- AI -> 生成 -> 编辑 -> 发送成功。
- OCR -> 识别 -> 编辑 -> 发送成功。
- ASR -> 转写 -> 编辑 -> 发送成功。

### P2：套餐和后台

目标：AI 能力商品化。

任务：

- 新增套餐管理。
- 新增用户套餐。
- 激活码绑定套餐类型。
- 用户详情显示套餐状态。
- 前端读取套餐权限。
- 未开通 AI 统一拦截。

验收：

- 管理员可开通 AI 1个月/1年/永久。
- 用户开通后 AI 入口可用。
- 到期后 AI 入口变为未开通/已到期。
- 硬件传输版用户可看到 AI 入口但不可用。

### P3：OCR/ASR 服务落地

目标：OCR/ASR 不再只是页面。

任务：

- 部署 OCR worker。
- 部署 ASR worker。
- 后端健康检查接入真实状态。
- 前端按状态展示。
- OCR/ASR 失败提供替代路径。

验收：

- 上传图片能得到文字。
- 录音能得到文字。
- 服务未配置/失败时用户不看到技术错误。

### P4：蓝牙发送与调试中心

目标：普通用户易用，内测售后可排查。

任务：

- 普通用户发送前准备页。
- 设备连接列表。
- 电脑系统选择。
- 发送速度选择。
- 设备调试中心。
- 编码模式只放调试中心。
- 发送协议读取系统/速度设置。

验收：

- 普通用户按步骤能完成发送。
- 售后能看到扫描、连接、写入日志。
- 调试中心能单字符测试。

## 11. 最终验收标准

### 用户体验验收

- 新用户 10 秒内知道从哪里开始。
- 首页不再像开发 demo。
- AI 未开通不再像功能坏了。
- OCR/ASR 不可用时有明确替代路径。
- 模板入口明显高于其他入口。

### 功能验收

- 硬件传输版可完成手动输入和基础模板发送。
- AI 套装版可完成 AI 创作和 AI 增强模板。
- OCR/ASR 可用时可完整进入发送链路。
- 未开通能力不会进入空页面。

### 后台验收

- 可创建 AI 套餐。
- 可给用户开通套餐。
- 可管理 1个月、1年、永久。
- 可查看用户套餐状态。
- 可处理到期、取消、延期。

### 技术验收

- AI/OCR/ASR 状态可被前端读取。
- 发送设置真正影响协议。
- 调试日志可定位蓝牙问题。
- 用户页面不出现开发术语。

## 12. 一次性解决后的目标形态

最终小程序应该变成：

```text
一个以模板为核心、AI 为增值能力、OCR/ASR 为输入增强、硬件为发送通道的文本发送产品。
```

而不是：

```text
一堆页面拼出来的硬件 demo。
```
