# 小程序信息架构与原型评审稿

> 状态：评审稿，不是 PRD。
> 目的：先统一产品方向、页面权重、用户主流程和原型结构。确认后再写正式 PRD。
> 约束：本阶段只整理设计方案，不继续改产品代码。

## 1. 当前判断

当前小程序更像功能 demo 集合，而不是面向用户的完整产品。

主要问题：

- 首页没有表达清楚产品核心任务：生成/整理文本，然后审核，再发送到电脑。
- 模板、AI、OCR、ASR 都存在页面或服务雏形，但入口分散，权重混乱。
- 模板本应是高频主入口，现在被藏在二级入口里。
- OCR/ASR 不是没有，但没有被纳入主流程。
- AI 前端有调用链，后端也有 `/api/ai/assistant` 网关，但当前本地后端 `aiConfigured=false`，所以真实 AI 创作尚未配置完成。
- 蓝牙设置页、电脑环境页、速度校准页存在，但没有形成完整的“设备调试中心”，也没有完全接入发送协议。
- 大量后台、QA、运营、合规页面混在主路由里，产品信息架构失焦。
- 页面文案里出现了偏开发/产品内部语言，例如“主流程”，不适合直接给用户看。

## 2. 产品核心定位

建议把产品定义为：

> 面向电脑输入场景的文本生成、整理与发送助手。

用户真正要完成的是：

1. 快速得到一段可用文本。
2. 自己确认内容没问题。
3. 把文本发送到电脑当前输入框。

因此主流程应该是：

```text
选择内容来源 -> 生成/识别/整理 -> 用户审核编辑 -> 发送到电脑
```

不是：

```text
先绑定设备 -> 找模板 -> 找 AI -> 找 OCR -> 再回来发送
```

## 2.1 产品模式与商业权限

需要明确区分两种用户模式。

### 模式 A：硬件传输版

用户能力：

- 可以连接硬件。
- 可以手动输入文本。
- 可以把文本发送到电脑。
- 可以查看历史记录。
- 可以看到 AI 相关入口，但不可直接使用。

AI 相关入口的表现：

```text
AI 写一段
未开通

点击后：
该功能需要开通 AI 套餐
请联系客服开通
[联系客服] [我知道了]
```

注意：

- 不要让用户配置 AI。
- 不要出现 `AI_BASE_URL`、`API_KEY`、`provider` 等开发配置词。
- 用户只感知“是否开通 AI 套餐”。

### 模式 B：AI 套装版

用户能力：

- 包含硬件传输版能力。
- 可以使用 AI 创作。
- 可以使用 AI 增强模板生成。
- 可以使用 AI 整理 OCR/ASR/手动输入后的文本。
- 是否包含 OCR/ASR，需要进一步确认它们是基础识别能力还是 AI 套餐能力。

AI 套餐档位：

```text
1 个月
1 年
永久
```

用户侧只展示：

- 当前套餐名称。
- 到期时间。
- 是否永久有效。
- 是否可续费/联系客服。

不展示：

- AI 服务商。
- API 配置。
- 模型配置。
- 网关状态。

### 权限判断建议

建议后端统一返回：

```text
hardwareEntitlement: active / expired / none
aiEntitlement: active / expired / none
aiPlanType: monthly / yearly / lifetime / none
aiExpireAt: date / null
```

前端只根据 entitlement 控制入口可用性。

## 2.2 管理后台新增：套餐管理

管理后台需要新增“套餐管理”，用于配置和分配 AI 套装。

后台能力：

- 新建套餐。
- 编辑套餐。
- 上架/下架套餐。
- 设置套餐时长：1 个月、1 年、永久。
- 设置套餐包含能力：AI 创作、AI 模板增强、OCR、ASR。
- 给用户开通套餐。
- 查看用户套餐状态。
- 续费、延期、取消。
- 导出套餐用户列表。

套餐字段建议：

```text
套餐名称
套餐类型：monthly / yearly / lifetime
有效期天数：30 / 365 / null
包含能力：AI 创作、AI 模板增强、OCR、ASR
状态：启用 / 停用
备注
创建时间
更新时间
```

用户套餐记录字段建议：

```text
用户
套餐
开通方式：后台开通 / 激活码 / 订单
开始时间
到期时间
状态：有效 / 已过期 / 已取消
是否永久
操作人
备注
```

## 3. 建议的信息架构

### 3.1 普通用户主结构

建议主结构压缩为 5 个用户可理解模块：

1. 首页工作台
2. 模板
3. AI 创作
4. 识别输入
5. 发送与历史

其中首页工作台承载最高频任务：

- 模板生成，最高权重。
- AI 创作。
- 拍照识别 OCR。
- 录音转写 ASR。
- 手动输入。
- 当前待发送文本。
- 发送到电脑。
- 设备连接状态。

### 3.2 开发/调试结构

这些能力不应该直接挤在普通用户主流程里：

- 蓝牙扫描详情。
- 服务 UUID / 特征值。
- 编码模式。
- 发送速度。
- MTU / 分片。
- ACK / 通知日志。
- 单字符测试。
- 长文本压测。
- 后端健康检查。
- AI/OCR/ASR provider 配置检查。

建议单独进入：

```text
设置 -> 设备与发送调试
设置 -> 服务配置检查
```

## 4. 首页原型

目标：用户一进来就知道“我可以用模板/AI/OCR/ASR 得到文本，然后发送到电脑”。

```text
┌──────────────────────────────┐
│ 顶部状态                     │
│ 设备：未连接 / 已连接 / 测试模式 │
│ 服务：已开通 / 待开通          │
└──────────────────────────────┘

┌──────────────────────────────┐
│ 常用模板                     │
│ 选择一个场景，填写信息后生成文本 │
│ [去选择模板]                  │
└──────────────────────────────┘

┌─────────┬─────────┐
│ AI 写一段 │ 拍照识别 │
├─────────┼─────────┤
│ 录音转文字 │ 手动输入 │
└─────────┴─────────┘

┌──────────────────────────────┐
│ 待发送文本                    │
│ [文本输入/生成结果区域]        │
│ 字数：0/5000                  │
└──────────────────────────────┘

┌──────────────────────────────┐
│ [发送到电脑]                  │
│ 未连接时：提示先连接或使用测试模式 │
└──────────────────────────────┘

┌──────────────────────────────┐
│ 最近发送                     │
│ 最近 3 条历史记录             │
└──────────────────────────────┘
```

首页文案原则：

- 不出现“主流程”“provider”“mock”“网关”等内部词。
- 普通用户看到的是“常用模板”“AI 写一段”“拍照识别”“录音转文字”“发送到电脑”。
- 测试模式只在开发态显示，文案为“本机测试模式”，不要伪装成真实设备已连接。
- 未开通 AI 套餐的用户仍可看到 AI 入口，但应有“未开通”状态，不要隐藏到用户完全不知道有这个能力。
- 点击未开通的 AI 能力时，引导“联系客服开通”，而不是进入空页面或报技术错误。

模板应该是最高权重入口。

### 5.1 模板列表

```text
┌──────────────────────────────┐
│ 模板                         │
│ 搜索模板 / 场景分类            │
└──────────────────────────────┘

分类：
[常用] [工作汇报] [通知] [邮件] [会议] [自定义]

模板卡片：
┌──────────────────────────────┐
│ 工作汇报                     │
│ 输入进展、问题、下一步计划      │
│ [使用]                       │
└──────────────────────────────┘
```

### 5.2 模板详情

```text
┌──────────────────────────────┐
│ 工作汇报                     │
│ 适合周报、日报、项目同步        │
└──────────────────────────────┘

字段：
- 本期进展
- 遇到的问题
- 下一步计划
- 语气：正式 / 简洁 / 口语

[生成文本]
```

### 5.3 模板结果

```text
┌──────────────────────────────┐
│ 生成结果                     │
│ [可编辑正文]                  │
└──────────────────────────────┘

┌──────────────────────────────┐
│ 发送前请确认                  │
│ - 时间是否准确                │
│ - 人名/数字是否准确            │

└──────────────────────────────┘

```

模板逻辑要求：

- 无 AI 时也应可生成基础文本，不能空白。
- 有 AI 时可增强润色，但必须明确“需要用户确认”。
- 模板结果应能回到首页待发送区域。
- 硬件传输版用户可使用基础模板。
- AI 套装版用户可使用 AI 增强模板。
- 如果某个模板必须依赖 AI，应在卡片上显示“AI 套餐”，未开通用户点击后引导联系客服。

## 6. AI 创作模块

当前状态：

- 前端：有 AI 对话页和结果审核页。
- 服务：`services/ai/assistant.js` 会调用平台侧 AI 服务。
- 后端：`/api/ai/assistant` 已存在。

## 7. OCR 模块

OCR 应作为首页一级内容来源出现，不应藏起来。

流程：

```text

```

结果页操作：

- 发送到电脑。
- 用 AI 整理，未开通 AI 套餐时显示开通提示。
- 套用模板。
- 保存草稿。

OCR 不可用状态：

```text

```

```text

```

## 11. 编码是否需要用户选择

普通用户不需要选择编码。

产品默认应该是：

```text
编码模式：自动
```

原因：

- 用户并不知道 VUC、RAW、ASCII 是什么。
- 编码是硬件协议和目标电脑输入环境之间的技术细节。
- 如果让普通用户选编码，会增加困惑。

但调试中心必须允许选择编码。

当前技术状态：

- `utils/encoder/vuc.js` 固定把中文/全角字符转成 `VUCxxxx`。
- `utils/ble/protocol.js` 固定使用 `SPD2|WIN11|` 前缀。
- `services/settings/transfer-settings.js` 有 `systemMode` 和 `speedMode`，但发送协议没有完全读取这些设置。

因此建议：

- 普通页面只显示“电脑系统”和“发送速度”。
- 调试页面才显示“编码模式”。
- 协议层需要真正读取 `systemMode`、`speedMode`、`encodingMode`。

普通用户主路径不应出现：

- QA 检查页。
- 发布验收页。
- 后台管理页。
- 后端健康页。
- Provider 配置页。

- 客户成功统计页。

这些页面可以保留，但入口应该迁移到：

```text

```

其中“套餐管理”不是删除，而是进入管理后台，并且需要成为后台核心模块之一。

后台建议结构：


## 13. 建议改动清单

### 首页

- 模板生成成为最大入口。
- AI 创作、OCR、ASR、手动输入作为同级来源。
- 显示当前待发送文本。
- 显示最近发送记录。
- 设备状态只作为状态，不抢主流程。

### 模板

- 模板列表增加分类、搜索、常用。
- 模板详情字段更贴近真实场景。
- 模板结果页支持编辑、审核、发送。
- 无 AI 时也能生成基础文本。

### AI

- 从聊天 demo 改为任务型创作。
- AI 不可用时给用户友好提示。
- 配置状态放到开发/服务配置页。

### OCR

- 首页一级入口。
- 结果页支持编辑、发送、AI 整理、套模板。

### ASR

- 首页一级入口。
- 结果页支持编辑、发送、AI 整理、套模板。

### 蓝牙/发送

- 普通用户流程简化。
- 新建设备调试中心。
- 编码模式只在调试中心出现。
- 速度/系统设置接入真实发送协议。

### 文案

- 删除所有开发者视角文案。
- 用户页面不用“主流程”“provider”“gateway”“mock”等词。
- 用任务语言：写一段、拍照识别、录音转文字、发送到电脑、连接设备。
