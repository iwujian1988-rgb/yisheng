# Code Review 清单

## 1. 蓝牙链路

- 是否有重复注册 `wx.onBluetoothDeviceFound` 或 `wx.onBLECharacteristicValueChange`。
- 页面卸载时是否停止搜索、断开连接、关闭 adapter。
- 写入前是否确认 deviceId、serviceId、characteristicId 都有效。
- 是否按 MTU 分片。
- 分片之间是否有延迟。
- token 之间是否有动态延迟。
- 发送中是否支持取消。
- 失败后是否清理 `sending` 状态和屏幕常亮。
- 日志是否不包含敏感病历全文。

## 2. VUC/token 编码

- 中文和中文标点是否转为大写四位 VUC。
- 英文、数字、单位是否按当前规则处理。
- 中英文边界是否有明确策略。
- 是否有测试样例覆盖病历常见文本。
- 是否避免把完整长文本一次性写入 BLE。

## 3. 账号与权限

- 登录接口是否统一走封装。
- token 是否集中存取。
- 401 是否统一跳转登录。
- 登录失败锁定策略是否只作为辅助，不替代服务端策略。
- 页面是否避免依赖伪登录状态。
- 登录、注册、微信登录后是否校验购买/开通状态。
- 是否区分未注册、未购买、已购买未绑定设备、设备被占用等状态。
- 后台创建付费用户是否有审计记录。
- 硬件设备绑定和解绑是否有权限校验。

## 4. 医疗数据安全

- 数据库存储是否避免明文病历。
- 管理员是否无法直接查看正文。
- 第三方 AI 调用前是否脱敏。
- 错误日志是否避免明文。
- 埋点是否只记录长度、类型、状态，不记录正文。

## 5. AI/OCR/ASR

- AI 请求是否经过脱敏网关。
- AI 输出是否要求用户确认后才进入发送链路。
- 提示词是否集中管理，避免散落在页面里。
- OCR/ASR 原始结果是否避免写入非加密日志。
- 第三方接口是否不接收可识别个人身份的信息。
- 低成本 AI 是否没有改动核心提示词和结果处理逻辑。

## 6. 页面和体验

- 按钮禁用态是否明确。
- 长操作是否有进度。
- 失败是否有可执行提示。
- 文案是否适合医生现场使用。
- 真机和模拟器差异是否有提示。

## 7. 已调通核心代码保护

- 是否保留现有蓝牙/VUC 发送行为。
- 是否只是封装、参数化、测试补齐或性能优化。
- 是否避免无依据重写核心发送逻辑。
- 是否提供修改前后测试样例。
- 是否保留回退路径。

## 8. 合并门槛

以下改动必须由 Codex 审查后合并：

- BLE、编码、发送队列。
- 登录、权限、加密、脱敏。
- 付费用户、购买状态、硬件设备绑定。
- AI/OCR/ASR 接口。
- AI 提示词、内容生成、病历整理逻辑。
- 项目配置和路由。
