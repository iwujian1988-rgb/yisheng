# AI 创作产品改造方案 V2

## 1. 改造结论

本次不把 AI 创作页继续做成“聊天框上叠一套表单”。页面只保留一个输入区、一个当前任务条和一个微信式加号面板。模板、文字、OCR、录音都是同一整理任务的输入来源，普通问答是一次性旁路，不进入任务材料。

目标用户是不理解提示词、工作区或上下文概念的普通用户。用户只需要知道三件事：当前整理成什么、已经提供了什么、下一步按哪个按钮。

## 2. 已确认的系统事实

### 前端状态

- `selectedTemplateId` 决定当前是否处于模板任务。
- `activeWorkspaceId` 是服务端工作区的唯一归属标识。
- 自由文字、OCR、录音先在客户端暂存，生成前同步到工作区。
- `composerMode=chat` 只允许下一条普通问答，发送后自动回到模板任务。
- OCR 和录音启动时记录 `workspaceId`，异步返回时不得写入后来选择的模板。

### 后端数据

- `ai_workspaces` 保存模板版本、字段、详细程度和材料版本号。
- `ai_materials` 按 `typed/ocr/asr/field` 保存来源，并以 `client_material_id` 保证幂等。
- `ai_generations` 冻结不可变 snapshot，生成过程不读取整个聊天历史。
- 专业工作区每次访问都重新校验会员、设备会话和在线证明。

### AI 请求

- 普通聊天只接收本次问题和独立 `contextId`。
- 模板生成只接收服务端 snapshot、模板生成合同和写作蓝图。
- 模板示例只提供格式模式，不能把示例事实带入正文。
- 输出拆成正文和待确认项；正文不得编造，待确认项用于提示真正影响使用的缺失信息。

## 3. 当前主要问题

1. 加号面板同时出现材料、模板设置、字段和普通聊天，大卡片过多。
2. 字段面板打开后还要再点“开始填写”，连续补充效率低。
3. 下一步提示没有排除已经填写的字段。
4. 生成确认层重复展示模板结构和详细程度，正文预览空间不足。
5. 用户直接输入疑似问题时，必须事先知道“普通问答”入口，否则可能误加入模板。
6. 质量检查可以发现数值和否定缺失，但待确认文本可能带重复标点或重复项目。
7. 短材料只能安全生成短草稿，不能通过编造内容强行拉长；提高价值必须依靠更顺畅的多来源采集和关键字段提示。

## 4. 新交互

### 未选模板

- 空状态只说明“直接输入；固定格式点加号选择模板”。
- 输入框处理普通对话或通用文本整理。
- 加号面板提供拍照识别、录音转写和选择模板。

### 已选模板

- 输入框上方只显示一个紧凑任务条：模板名称、接下来可补充的三个字段、填写字段按钮。
- 任务条始终显示尚未填写的字段，不重复提示已填写项。
- 点“填写字段”直接看到字段列表，不再经过第二层开关。
- 加号面板固定为四个等宽入口：拍照识别、录音转写、更换模板、普通问答。
- 文字、图片和录音属于当前模板；普通问答明确不加入模板，发送后自动返回。
- 疑似独立问题在发送前弹出用途选择：“仅回答这个问题”或“加入当前整理”。系统不靠语义猜测直接改写数据。
- “就这样，开始写吧”识别为生成动作，不写入正文材料。

### 生成确认

- 只展示模板名称、材料来源摘要、图片缩略图和合并后的材料预览。
- 主按钮为“材料无误，生成草稿”，次按钮为“返回修改”。
- 详细程度与最终栏目收进字段面板的“生成设置”，不在确认层重复出现。

## 5. 数据边界

```text
用户选择模板
  -> POST /api/ai/workspaces
  -> 获得 activeWorkspaceId

文字/OCR/录音/字段
  -> 始终绑定 activeWorkspaceId
  -> 生成前写入 ai_materials / field_values

用户确认生成
  -> POST /api/ai/workspaces/:id/generations
  -> 冻结 templateVersion + fields + included materials + inputRevision
  -> /api/agent/chat/stream 只读取 generation snapshot

普通问答
  -> 不带 workspaceId、generationId、templateId
  -> 使用独立 sideChatContextId
  -> 回答后丢弃该上下文并返回模板任务
```

任何异步结果必须使用操作开始时捕获的工作区 ID。切换模板只创建新工作区，不迁移旧材料。

## 6. 输出质量策略

- 模板生成合同决定允许出现的章节和禁止推断项。
- 写作蓝图决定标题顺序、段落写法、事实展开方式和篇幅信号。
- 质量检查保留所有数值、单位、时间、否定和不确定性。
- 草稿过度压缩时允许一次自动重写，但只能使用已有事实补足完整句和时间线。
- 待确认项去除序号残留、尾部重复标点和重复项目。
- 不以固定字数作为成功标准。大病历是否足够完整取决于输入材料覆盖度，界面负责低成本提醒关键字段。

## 7. 验收标准

- 选择模板后，首屏能看到模板名称和三个下一步字段，不需要展开面板。
- 点填写字段后可连续填写两项，面板不会关闭，也不再多点一次。
- 已填写字段不会继续出现在“接下来可补充”提示中。
- 加号面板最多四个等宽入口，图标和文字同轴居中。
- “今天天气怎么样”不会直接进入模板快照，必须先确认用途。
- 普通问答不携带模板、工作区、字段、OCR或录音数据。
- 快速切换模板、迟到 OCR/录音、登录恢复均不串数据。
- 生成确认层不被底部导航遮挡，键盘弹出时主操作仍可见。
- 五组模板真实评测保留至少 80% 关键事实，不增加禁止事实，不在正文输出空字段占位。
- 全量发布检查、组件依赖检查和微信开发工具编译通过后才允许发布。
