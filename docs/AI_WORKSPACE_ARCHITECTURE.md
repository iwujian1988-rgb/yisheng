# AI 创作工作区改造方案

## 1. 目标

把当前“页面里临时拼接文字后调用 AI”的流程，改造成可恢复、可隔离、可追溯的通用写作工作区。

本次改造解决：

- 新模板与旧模板的材料互不污染；
- 普通聊天不自动进入当前文档；
- 字段、自由输入、OCR、录音可以共同参与生成，同时保留来源；
- OCR、录音异步返回时仍归属于发起操作时的工作区；
- 登录失效、页面重载、设备短暂断开后可以恢复草稿；
- “就这样，开始写”等明确指令触发生成，不作为正文材料；
- 每次生成基于不可变材料快照，支持补充后生成新版本。

## 2. 不可破坏的产品边界

### 2.1 微信内部审核原则

- 公共界面继续使用“模板、字段、材料、记录、整理、生成”等通用表达。
- 不新增诊断、治疗、处方、问诊等面向用户的能力或文案。
- AI 只整理用户提供的材料，不替用户作专业结论。
- 专业模板、字段和规则由后端在授权后下发，客户端不新增专业静态数据。
- 登录失效、设备断开或接口失败时，不得意外显示专业模板。

### 2.2 现有硬件权限原则

专业能力继续使用现有准入链路，不创建旁路：

1. 会员有效；
2. 设备已绑定；
3. 蓝牙当前真实连接；
4. `X-Device-Session` 会话有效且具有对应 capability；
5. `X-Device-Live` 在线证明有效。

设备会话、在线证明和会员校验由后端逐请求复验。不能只在选择模板时验证一次，也不能相信前端传入的专业模式。

蓝牙连接和基础文本传输仍不受会员 gate 影响；只有 AI、模板和专业处理能力在业务入口检查会员及专业权限。不得在小程序启动时主动申请蓝牙权限。

## 3. 当前系统事实

- `documentContextId` 是前端临时 ID，不是数据库文档实体。
- 工作区草稿只保存部分输入、录音文字、模板和字段，图片及会话没有完整持久化。
- 模板字段当前按中文标签存值，嵌套字段存在同名冲突风险。
- 字段值最终被渲染为文本，与自由输入拼接后发送给 AI。
- OCR 和录音结果没有绑定工作区，异步返回可能落入后来选择的模板。
- Agent 会话只存在 Python 进程内存中，会过期且服务重启后丢失。
- 当前路由器只支持文本任务，不具备可靠的“普通聊天/字段回答/加入材料/开始生成”状态机。
- 现有 SQL Store 会把整表加载进内存并周期性全量 upsert，不适合承载持续增长的工作区和材料流水。

## 4. 核心数据模型

### `ai_workspaces`

- `id`：工作区 ID；
- `user_id`：所属用户；
- `template_id`、`template_version`：使用的模板及版本；
- `audience`：`general` 或 `professional`，由服务端模板确定；
- `detail_level`：简洁、标准、详细；
- `status`：`active`、`locked`、`archived`；
- `field_values`：以稳定字段路径为 key 的 JSON；
- `material_revision`：材料或字段每次变化递增；
- 创建、更新时间。

### `ai_materials`

- `id`、`workspace_id`、`user_id`；
- `kind`：`typed`、`ocr`、`asr`、`field`；
- `text`：脱敏后的材料文字；
- `field_key`：字段回答对应的稳定路径；
- `client_material_id`：客户端幂等键；
- `status`：`pending`、`included`、`excluded`、`failed`；
- `source_meta`：图片、录音时长等非敏感元数据；
- 创建、更新时间。

### `ai_generations`

- `id`、`workspace_id`、`user_id`；
- `input_revision`：本次生成使用的材料版本；
- `idempotency_key`：防止重复点击重复生成；
- `snapshot`：本次采用的模板版本、字段和材料不可变快照；
- `body_text`、`pending_items`；
- `status`：`running`、`completed`、`failed`；
- 创建、完成时间。

高频工作区数据使用独立 Repository 直接查询 SQL；测试和本地无数据库模式使用内存实现。不加入旧的全量内存 Store 持久化循环。

## 5. 交互状态机

### 5.1 选择模板

- 服务端创建新的工作区并立即返回字段列表；
- 新模板默认不继承上一个模板的材料；
- 旧工作区保留，可在“最近整理”中恢复；
- 页面立即展示下一步：“直接输入材料，或补充建议字段”；
- 主界面只保留一个主操作，根据状态显示“开始整理”或“更新内容”。

### 5.2 输入归属

- 用户主动点击字段后，下一次提交确定性写入该字段；
- OCR、录音在操作开始时捕获 `workspaceId`，返回时仍写入原工作区；
- 普通输入默认先作为待确认材料，不直接进入生成快照；
- 明确点击“加入当前整理”后变为 `included`；
- 明确生成命令由状态机识别为动作，不写入材料；
- 无法确定用途的输入不得由 AI 直接修改工作区，必须由后端返回建议动作，由用户确认。

### 5.3 生成

- 后端依据 `workspaceId` 重新检查模板权限；
- 冻结模板版本、字段值和 `included` 材料形成 snapshot；
- 生成过程不读取整个 Chat 历史；
- 同一 `input_revision + idempotency_key` 只生成一次；
- 生成后返回正文和建议补充项；补充材料后 `material_revision` 递增，再生成新版本。

### 5.4 设备断开

- 保留工作区和用户草稿，不自动切换为普通模板；
- 专业工作区显示通用锁定提示“连接设备后继续”；
- 后端拒绝读取专业模板详情、写入材料和生成；
- 重新连接并取得有效在线证明后恢复同一工作区。

## 6. API

- `POST /api/ai/workspaces`：选择模板并创建工作区；
- `GET /api/ai/workspaces/:id`：恢复工作区；
- `PATCH /api/ai/workspaces/:id`：修改详细程度或归档；
- `POST /api/ai/workspaces/:id/fields`：按稳定字段路径保存字段；
- `POST /api/ai/workspaces/:id/materials`：添加文字/OCR/录音材料；
- `PATCH /api/ai/workspaces/:id/materials/:materialId`：加入或排除材料；
- `POST /api/ai/workspaces/:id/generations`：冻结快照并创建生成版本；
- 原 `/api/agent/chat` 保留给普通聊天和兼容旧版本，新工作区生成不得依赖 Chat 历史。

所有工作区 API 必须验证用户所有权。专业工作区每次访问还必须复用 `contentAccess` 的会员、设备 capability 和在线证明校验。

## 7. AI 输入合同

AI 只接收服务端生成的 snapshot：

```json
{
  "workspaceId": "aiw_xxx",
  "template": { "id": "...", "version": 3, "contract": {}, "blueprint": {} },
  "detailLevel": "standard",
  "fields": { "diagnoses.discharge_diagnosis": "..." },
  "materials": [
    { "id": "aim_xxx", "kind": "ocr", "text": "..." }
  ],
  "inputRevision": 4
}
```

生成要求：保留事实、数值、时间、否定和不确定性；允许补充语法、连接和结构，不允许补充新事实。范文事实不进入模型，使用生成合同和写作蓝图控制格式与丰富程度。

## 8. 验收标准

- 连续选择两个模板，后一个模板不读取前一个模板材料；
- OCR/录音处理中切换模板，结果仍归原工作区；
- 相同中文标签但不同字段路径可以分别保存；
- “今天天气怎么样”不会进入生成快照；
- “就这样吧，开始写”触发生成且不出现在正文；
- 登录后可恢复当前工作区、字段和已确认材料；
- 专业工作区断开设备后不能继续调用专业生成，重连后恢复；
- 仅绑定设备、仅传 `connected=true`、过期会话或过期在线证明均不能获得专业能力；
- 通用流程不主动请求蓝牙权限；
- 客户端包不新增专业静态文案或模板数据；
- 现有 BLE、发送、OCR、ASR、模板和发布检查全部通过。
