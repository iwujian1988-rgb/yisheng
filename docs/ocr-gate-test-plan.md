# OCR 小样本闸门测试计划

> 版本：v1.1  
> 日期：2026-06-08  
> 状态：待执行  
> 预计耗时：1-2 小时

## 1. 测试目标

本次测试不是最终准确率验收，而是判断 OCR 链路是否值得继续投入主链路开发。

必须回答 4 个问题：

| # | 判定问题 | 期望 |
|---|---|---|
| Q1 | OCR worker 能否正常启动并返回稳定 JSON 结果？ | 是 |
| Q2 | 清晰中文段落是否基本可读，允许少量错字？ | 是 |
| Q3 | OCR 结果能否进入用户确认页，而不是直接发送？ | 是 |
| Q4 | 失败时是否有明确错误提示，而不是静默失败？ | 是 |

4 项全部为“是”，闸门通过；任意一项为“否”，先修再测。

## 2. 样本要求

共准备 5 张图片。所有内容必须为虚构或非敏感公开文本，不得使用真实患者信息、真实病历、真实检查报告、真实处方或真实身份证明材料。

样本可以由 Word/WPS 排版后截图，也可以打印后拍照。测试图片不得提交到任何未批准的外部 API。

| 样本 | 类型 | 制备方式 | 预期难度 |
|---|---|---|---|
| S-01 | 清晰打印中文段落 | Word/WPS 输入虚构健康科普或办公说明，截图保存 PNG | 低 |
| S-02 | 手机拍摄略倾斜中文段落 | 打印 S-01，以 15-20 度倾斜角拍摄 | 中 |
| S-03 | 表格样式图片 | 制作 3 行 x 4 列虚构数据表，截图保存 | 中 |
| S-04 | 低光/轻微模糊图片 | 低光环境拍摄 S-01，文字肉眼仍可辨认 | 中高 |
| S-05 | 中英文数字混排图片 | 输入中文、英文、数字、标点混排的虚构说明文本 | 中 |

S-05 建议文本方向：

```text
设备测试记录 A-102：本次传输包含中文、English words、数字 12345、单位 2.3mm、比例 4.1%、日期 2026-06-08。请核对 L2-L3、L4-L5、USB-C、Wi-Fi、BLE 5.0 等混排内容是否被正确识别。
```

## 4. 通过标准

单条记录判定：

| 结论 | 条件 |
|---|---|
| 通过 | 成功返回，错字数 <= 3，漏字数 <= 2，换行可接受为 `Y`，且进入确认页 |
| 观察 | 成功返回，但错字 4-8 个、漏字 3-5 个，或换行为 `部分`，内容仍可辨认 |
| 失败 | 未返回、返回乱码、错字 > 8、漏字 > 5、未进入确认页、静默失败无提示 |

整体闸门判定：

| 条件 | 结果 |
|---|---|
| 5 张中至少 3 张在 PaddleOCR 上通过 | 闸门通过 |
| S-01 在 PaddleOCR 上未通过 | 闸门不通过 |
| 服务崩溃、无响应超过 30 秒、或超时无明确错误 | 闸门不通过 |
| OCR 结果绕过用户确认页直接发送或进入 AI | 闸门不通过 |

## 5. 安全红线

触碰任意一条，立即停止测试并修正：

1. OCR 结果未经用户确认就发送到目标电脑。
2. OCR 结果未经用户确认就进入 AI 整理流程。
3. 服务端日志打印完整图片 base64、原图、完整 OCR 文本或其他敏感正文。
4. 未脱敏测试图片被提交到任何外部 API。
5. 使用真实患者、真实病历、真实检查报告、真实处方或真实身份证明材料。

补充检查：

- OCR 识别页不得把长识别正文直接拼进页面 URL。
- 确认页应从临时结果 key 或等价安全载体读取 OCR 结果。
- 用户点击“确认使用”前，OCR 结果只能展示和编辑/核对，不得进入草稿、AI 或发送链路。

## 6. 风险记录

| # | 风险 | 概率 | 影响 | 缓解措施 |
|---|---|---|---|---|
| RK-01 | PaddleOCR 清晰中文准确率低于预期 | 中 | 高 | 与 RapidOCR 对比，必要时调整默认引擎 |
| RK-02 | 表格结构识别错乱 | 高 | 中 | 闸门阶段标记为观察，后续再做表格后处理 |
| RK-03 | 手机角度/透视导致识别率下降 | 中 | 中 | 评估是否需要拍摄提示或预处理 |
| RK-04 | 图片过大导致上传慢或超时 | 低 | 中 | 记录图片体积，超过 3MB 标注备注 |
| RK-05 | 低光/模糊图片不可用 | 高 | 低 | 产品侧提示用户在光线充足处拍摄 |
| RK-06 | 日志意外记录敏感内容 | 低 | 高 | 只记录请求 ID、耗时、状态码、体积等元数据 |

## 7. 后续动作

闸门通过后：

1. 将 PaddleOCR 接入主链路：拍照 -> 上传 -> OCR -> 用户确认 -> 草稿/发送。
2. 保留 RapidOCR 作为备选评估，不在闸门阶段做复杂自动降级。
3. 上线前再准备 30-50 张全部脱敏的样本做准确率验收。

本次不测：

- 手写体识别。
- 大批量并发压测。
- 自动旋转/方向检测。
- 表格结构化还原。
